# Codex instructions for Kimodo

## Required tools and runtime

- Use `mmd-mcp` for all operations performed in MikuMikuDance (MMD). Do not use generic screen or mouse/keyboard automation to operate MMD when `mmd-mcp` can perform the requested action.
- When generating motion with Kimodo, always use this repository's `.venv` by invoking `.\.venv\Scripts\python.exe` directly. Do not use a global Python interpreter or rely on shell activation.

## Motion generation from natural-language requests

When the user asks Codex to create a motion, treat the request itself as authorization to run `.\.venv\Scripts\python.exe -m kimodo.scripts.generate` in this repository.

- Accept motion descriptions in Japanese or English. Translate Japanese descriptions into concise, natural English prompts suitable for Kimodo.
- Always run motion generation with this repository's `.venv` interpreter by invoking `.\.venv\Scripts\python.exe` directly. Do not use a global Python interpreter or depend on shell activation.
- Preserve the requested subject, action sequence, direction, body side, speed, style, and timing. Do not invent important motion details that could change the user's intent.
- Separate sequential actions into period-delimited English sentences because `generate` treats each sentence as a separate prompt segment.
- When the user provides per-action timing, pass matching space-separated values to `--duration`. The number of duration values must equal the number of prompt sentences. When timing is unspecified, use the command's defaults rather than blocking on clarification.
- Map explicit requests for sample count, diffusion steps, transition frames, constraints, seed, model, CFG settings, post-processing, BVH, VMD, VMD model name, VMD scale, or demo-compatible output to the corresponding command-line arguments.
- When the user does not specify an output format, include `--vmd` and produce VMD output by default. If the user explicitly requests another format or explicitly says not to create VMD, follow that request instead.
- Unless the user specifies a text-encoder device or `TEXT_ENCODER_DEVICE` is already set, set `TEXT_ENCODER_DEVICE=cpu` in the generation process environment so the text encoder is offloaded to the CPU. Do not overwrite an existing value.
- Use a short, descriptive output stem under `outputs/` unless the user specifies an output path.
- Before execution, briefly show or state the English prompt being used. Then run the command and report the generated output paths and any errors.
- Ask a clarifying question only when an ambiguity would materially change the motion. Otherwise, make a conservative assumption and proceed.

Example:

```powershell
if (-not $env:TEXT_ENCODER_DEVICE) {
  $env:TEXT_ENCODER_DEVICE = "cpu"
}
.\.venv\Scripts\python.exe -m kimodo.scripts.generate `
  "A person walks forward. They stop and wave their right hand." `
  --duration "3.0 3.0" `
  --vmd `
  --output outputs/walk_and_wave
```

## Applying generated VMD motion to an MMD model

When applying a Kimodo-generated VMD file to a model in MMD, do not apply the original generated VMD directly. First resize it for the destination model with VmdSizing, then apply the newly generated resized VMD file.

- Use the exact full path of the VMD file generated by Kimodo as `--motion_path`.
- Use `kimodo\assets\mmd\kimodo_reference.pmx` as `--org_model_path`.
- Use the exact full path that was specified when the destination model was loaded into MMD as `--rep_model_path`. Do not substitute only the model filename or guess its location. If that full path is unavailable, ask the user for it before running VmdSizing.
- Enable both detailed stance correction and twist correction by passing `--detail_stance_flg 1 --twist_flg 1`.
- Run the following command from the repository root, quoting all paths:

```powershell
.\VmdSizing_5.01.08_64bit_cli.exe `
  --motion_path "<absolute path to the Kimodo-generated VMD>" `
  --org_model_path "kimodo\assets\mmd\kimodo_reference.pmx" `
  --rep_model_path "<absolute path originally used to load the destination model into MMD>" `
  --detail_stance_flg 1 `
  --twist_flg 1
```

- After VmdSizing finishes, identify the VMD file newly created in the `outputs` folder. Its filename is the original VMD filename with the destination model name, date, and time appended.
- Apply that newly created resized VMD to the model currently loaded in MMD. Never apply the original Kimodo-generated VMD when this sizing workflow is requested.
- Report both the original generated VMD path and the resized VMD path.
